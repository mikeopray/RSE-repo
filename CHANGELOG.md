## 1.3.5
RELEASE CANDIDATE. Built on 1.3.4. Root-cause fix for the overlapping lines found on the partner's phone recording, plus an automatic fallback. No quality gate or threshold changed.
- Root cause (2026-10-19, reproduced from her audio): on the Parakeet path each speech chunk is widened outward until the signal level drops below 3x the noise floor. In a room whose background level stays above that (her recording: 70-120 against a threshold of 52) the windows grew across whole pauses (up to 48 s for a 2 s line) and overlapped their neighbours by 92.8 s; the cut then used the same audio twice. `engine/takes_parakeet.py` `refine_chunks` now (a) never widens a window by more than 1.0 s per side and (b) splits each pause at its middle between neighbours, so windows cannot overlap by construction. Soft onsets and tails in normal recordings need under 0.3 s (p90 0.05-0.20 s over 5 lab recordings).
- Regression (11 real recordings from the owner's Downloads folder, 18-355 s, phone and WhatsApp, Spanish and English; old vs new widening, same pad search): window overlap old 0.0-2.0 s -> new 0.0 s on all 11; the cut check went FAIL -> PASS on one recording (WhatsApp 2026-10-05, 1.7 s overlap before) and PASS -> PASS on 8; 2 recordings (IMG_1453, WhatsApp 2026-10-16) still stop on `median gap 0.07 / 0.065 outside 0.08-0.12` because the speaker's own pauses are shorter than the target (0 ms of voiced audio lost, no overlap) - OPEN, needs an owner decision on the gate. The partner's recording: overlap 92.8 s -> 0 s, longest window 48 s -> 6.9 s, cut PASS (pad 0.10 s, 23 pieces, 0 ms voiced lost, 0 ms audio repeated).
- Automatic fallback (2026-10-19): in `auto`, if `cut` stops on a project analysed with Parakeet, the speech analysis is redone with the Whisper workflow and `cut` runs again (a note says so); leftovers of the Parakeet analysis (`pk_words.json`, `engine`) are removed whenever the Whisper workflow runs. NOT run end to end yet (the engine cannot be started without a licence here): the partner test is its first real run.
- QUALITY GATE CHANGE (approved by the owner 2026-10-19): the cut check's median-gap rule. OLD: a median gap outside 0.08-0.12 s always stopped the edit. NEW: a median gap BELOW 0.08 s no longer stops it when no voiced audio was lost, no raw audio is used twice (overlap 20 ms or less) and no gap exceeds the 0.20 s cap; the cut log says the speaker's pauses are shorter than the target (note). A median ABOVE 0.12 s, or any of the other conditions, still stops the edit. Thresholds (0.08-0.12 s, 0.20 s cap, 20 ms overlap) unchanged. Why: padding cannot add silence that is not in the recording; two of 11 real recordings (fast talkers, 0.07 and 0.065 s) were stopped although nothing was lost. After the change both pass; the other nine were passing and are unaffected (the change only removes this one failure under those conditions).
- Kept from 1.3.4: if the Parakeet lines still overlap by more than 1.0 s in total the Whisper workflow is used.

## 1.2.0-speed-test
TEST BUILD, not published. Identical to 1.1.0-parakeet-test (same speech stages) plus three lossless speed-ups. 1.1.0-parakeet-test and every other version folder are untouched.
- `frame` matte: `engine/segbatch_par.py` runs the Apple Vision matte tool on 3 processes at once instead of 1 (same masks, byte-identical on the 300-frame test; 2.2-2.4x faster). `RSE_MATTE_PROCS=1` = old behaviour. Wired in through `rse_platform.matte_cmd` (Mac only; Windows unchanged).

The video is frame-identical to the two renders, the audio is sample-identical to the old join. It checks that both parts have the same codec/size/frame rate/colour tags and the same frame count and falls back to the old re-encode join if anything differs. The file is about 1.4x larger (keeps the render bitrate). `RSE_FAST_JOIN=0` = old re-encode join.
Not changed (not verified as safe without a full pipeline run): the caption gate position, hook/body render reuse, render presets, the pixel gate.

## 1.0.17
Not published yet. Builds on 1.0.16; only the word-recall part of the cut check changed.
- The word-recall gate (how much of the transcript the speech recogniser finds again in the cut audio) no longer stops an edit when the shortfall is only the recogniser's own doubt (names, numbers, mumbled words): if recall is between 90 % and 98 % and no voice was cut away and no audio is repeated, the edit continues and the cut log says so in a note (check those words in the captions). Below 90 %, or below 98 % together with real damage (voice lost, audio played twice), it still stops. On real recordings that stopped at 93.5 %, 95.5 % and 97.8 % with nothing cut away, the edit now continues.
## 1.0.16
From the first real edit on a clean 1.0.15 install (the cut check stopped a customer's video for 70 ms of "lost voice"). Only the cut planner and its check changed; pause lengths (median 0.08-0.12 s, cap 0.2 s, 40:60 padding) are untouched.

- Captions: a word the speech recogniser repeats (often the last word of a line, sometimes several times) is removed using the line's first-pass text as the reference; real repeats ("very very", "bye bye") are kept. The cut log reports how many were removed.
## 1.0.10
- Memory: the one-command edit now runs every stage as its own program, one after another, so the speech model (about 3.5 GB) is released before the video work starts (a one-process version could run a 8-12 GB computer out of memory on long videos). If the system stops a stage for memory, the message says so and finished stages are kept.
- The video renderer's parallel Chrome windows are limited from the computer's memory and cores (and a low-memory mode on small computers) instead of "as many as possible".
- Every stage records its time and peak memory (shown in the support report), so a problem on any computer can be diagnosed from real numbers.

- Fix: a line spoken at the very start of the recording could be lost from the captions (the cut began before time 0). Spans are now kept inside the recording.
- Fix: speech recognition now always runs on the CPU, so a PC with a graphics card but no CUDA libraries no longer crashes.
- Safety net: a repeated last word of a line (a known recogniser habit on short clips) is removed.
- The renderer's headless browser is now downloaded and verified at setup (setup stops with a clear message if it fails) and the health check tests for it; the Hugging Face symlink warning is silenced.
